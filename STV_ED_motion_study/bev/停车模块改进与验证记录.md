# 纯电动车停车模块改进与验证记录

日期：2026年11月3日。当前实现是纵向停车工程基准，供后续路径与速度规划调用，不作为论文方法创新。上一版bev_probe.py及其results目录保留；新代码是stopping_v2.py，输出在results_stopping_v2。

## 1 结果与适用边界

共设置48种输入组合：初始速度0、1.5、3、4 m/s，初始能量分数0.55和1.00，电池温度25和−5°C，实际摩擦制动时间常数0.12、0.18和0.35 s。控制器的名义摩擦制动时间常数固定为0.18 s，因此包含响应参数失配。

| 指标 | 结果 |
|---|---:|
| 总输入组合 | 48 |
| 找到参考轨迹并完成两次停车 | 36 |
| 完成工况中两次停车均满足±0.10 m工作目标 | 36 |
| 完成工况最大停车位置绝对误差 | 0.0072913 m，约7.3 mm |
| 完成工况最大近零速保持位移 | 0.0005691 m，约0.57 mm |
| 0.02 s步长下完成工况的最大原始加加速度幅值 | 1.2653 m/s³ |
| 当前参考族与约束下未找到轨迹 | 12 |

±0.10 m是本项目工作目标，不是行业标准。以上精度仅针对无噪声、平路、假设参数的仿真，不能当作实车精度或安全保证。

12组未找到参考轨迹的输入均为4 m/s初始速度、10 m可用停车距离。搜索限制为七次位置多项式、指定时长范围，以及采样检查的速度、加速度、加加速度条件。**这只表示该参考轨迹族内未找到方案，不证明汽车在物理上无法停下，也不能归类为碰撞或控制执行失败。**

独立补充工况把初始4 m/s、低温、慢摩擦制动响应的第一停车距离改为15 m，第二目标位置相应改为45 m，完成后两次误差约−1.2 mm和3.8 mm。这个工况改变了可用距离，不能与10 m工况冒充等条件优劣比较。

## 2 具体改动

### 位置与速度共同反馈

旧版以剩余距离生成速度目标，随后主要依赖速度误差控制，停车位置误差约0.34–0.43 m。新版使用同时给出位置、速度和加速度的时间参考，再加入位置与速度反馈。没有将车辆位置直接赋成目标位置，轨迹位置始终来自速度积分。

参考位置采用七次多项式，首末端约束位置、速度、加速度和加加速度。参考时间通过搜索确定，并用301个采样点检查导数条件：速度不超过max(3 m/s,初始速度)，加速度绝对值不超过1.1 m/s²，加加速度绝对值不超过1.5 m/s³。这不是连续时间约束证明。

反馈请求为：

\[
a_{des}=a_{ref}+0.8(x_{ref}-x)+1.8(v_{ref}-v),
\]

随后施加请求加速度及变化率限制。新增参考和反馈均属基准工程实现，不声称是新控制理论。

### 显式区分控制器与执行对象

控制器输出电机转矩指令及摩擦制动指令。独立执行对象再施加电机转矩/功率限制、转矩响应及变化率、再生能力约束、摩擦制动响应和道路阻力。

控制器采用名义一阶执行环节的逆模型作前馈，并根据预测实际电机力补充分配摩擦制动力。测试中实际摩擦制动时间常数与控制器参数可以不同。该实现用于建立可解释的执行基线，尚未包含传感噪声、参数辨识和更复杂液压特性。

### 明确减速、保持与起步状态

第一目标位置为10 m，达到终端条件后近零速保持2 s；第二目标为40 m，再保持1 s。保持入口条件为：参考已到终端、速度小于0.002 m/s、位置误差小于0.05 m、实际加速度绝对值小于0.05 m/s²。

保持指令采用零电机转矩与300 N摩擦制动能力。未把实际速度直接置零，保持段仍通过执行模型与位置积分计算，因此“保持位移”可被单独检验。该部分只适用于当前平路模型，不是坡道保持系统。

## 3 零速数值效应的检查与处理

最初只改进参考和控制器时，停车位置误差已降至毫米级，但将步长从0.02 s减到0.01 s，部分工况的原始加加速度峰值仍明显增大。相关诊断保存在diagnostics_before_regularization.json，未删除失败证据。

问题与近零速处固定滑动摩擦力及速度非负截断有关。现在摩擦执行状态表示制动力能力B，实际低速滑动摩擦近似为：

\[
F_b(v)=B\tanh(v/v_\epsilon),\qquad v_\epsilon=0.03\ \mathrm{m/s}.
\]

它是数值正则化，不是实测制动图谱。完全静止时按前进方向约束处理，制动力不使车辆向后运动。不能把正则化曲线当作真实轮胎/制动系统低速特性的证明。

选定三组工况的步长检查：

| 初始速度、温度、实际制动响应 | 停车误差变化最大值 | 原始加加速度峰值，0.02 s→0.01 s |
|---|---:|---:|
| 0 m/s、25°C、0.18 s | 0.0009824 m | 0.9274→0.9256 m/s³ |
| 0 m/s、−5°C、0.35 s | 0.0021097 m | 0.9274→0.9460 m/s³ |
| 3 m/s、−5°C、0.35 s | 0.0027694 m | 0.9149→0.8939 m/s³ |

这些工况中，峰值不再出现此前明显的步长缩小放大现象。它们只支持所选算例的数值稳定性，不能外推为整个系统收敛证明或实车舒适性认证。

另对一个低温慢制动工况扫描vε=0.02、0.03、0.05 m/s，均满足停车目标，最大停车误差约7.8 mm。该敏感性测试仍很有限，后续接入更复杂场景时需继续保留。

## 4 验证完成情况

新增4项测试通过：

1. 平路静止时无非物理蠕行或额外回收，电池仅承担辅助用电。
2. 保存的车辆位置与速度、加速度积分一致，未通过位置跳变“修正”停车误差。
3. 有参考工况满足终端误差和保持漂移条件；无参考输入明确保留并分类。
4. 运动步内功—动能关系及电池能量更新一致。

另外完成48组输入扫描、3组步长细化、3个正则化参数和一个15 m预瞄距离补充算例。具体数据见sweep.json、sweep.csv、verification.json和run_metadata.json。

本轮只改善纵向停车基线，尚未把该模块接入二维道路和动态行人规划。旧版与新版使用不同的参考轨迹和控制器，因此不能把误差差值包装成严格的同参考控制算法性能比较。

## 5 如何轮流接着工作

统一入口为STV_ED_motion_study/WORK_LOG.md。每次继续时先阅读最新状态，再看本报告和results_stopping_v2中的数据；不要用旧版results作为新版结论。

在bev目录运行：

```powershell
python stopping_v2.py
python verify_stopping_v2.py
python plot_stopping_v2.py
```

模型需要NumPy，绘图另需Matplotlib。原始bev_probe.py和results保留用于追溯。

下一项工作是把此纵向控制模块接回二维车辆运动，并加入单个动态横穿对象。首先验证“未进入、减速进入、提前停车”三类运动都能正确执行与回放，再研究执行状态相关的通过时间约束。对没有参考轨迹的输入应由上层调整初始速度、预瞄距离或采用经验证的替代轨迹，不能直接进入通道。当前尚无经验证的紧急回退算法。
