# 纯电动车二维横穿场景联调记录

日期：2026年11月3日。本轮将纵向停车模块v2接入二维运动，加入一个动态横穿对象，验证车辆执行、车身碰撞检测、停车与再起步。当前是可回放的功能验证平台，不是已证明创新的规划算法。

## 1 当前可以执行的内容

- 车辆在一条带平滑横向偏移的参考路径上行驶，采用运动学自行车模型、纯追踪转向、转角及转角变化率限制。
- 纵向通过stopping_v2的转矩/摩擦制动接口执行，保留电机响应、再生限幅、摩擦制动滞后、电池能量分数和低速摩擦正则化。
- 使用4.5 m×1.8 m车体矩形，参考点为后轴中心，前悬方向占3.5 m、后方占1 m。
- 对车身与圆形行人执行几何检测；车身与矩形路侧摊位采用分离轴检测；道路边界检查覆盖车身各角点。
- 比较直接通过、全程低速、先停车再等待，以及基于预测结果选择有限候选的策略。
- 停车后每0.5 s检查一次起步方案，实际电机、制动及电池状态在等待期间继续变化。

横向参考路径目前固定，不会围绕行人主动生成新的绕行路径。因此，这一轮完成了二维跟踪与碰撞联调，尚未完成横纵联合轨迹优化。

## 2 场景与输入

道路横向边界为y=±3 m。两侧矩形摊位位于x=13–24 m范围，其内侧边界为y=±1.6 m，使局部有效通路收窄为3.2 m。

参考路径为y=0.25 sin²(πx/40)，使用弧长参数化。停车等待姿态的参考点约为x=15.4 m，车辆前部位于横穿位置之前；是否接触仍由完整车体检测决定，不能仅依赖这一位置描述。

行人为半径0.3 m的圆，沿x=20 m横穿，速度固定1 m/s。中心经过y=0的时刻分别设为2、14、17、25、28 s。这些是为覆盖通行与冲突分支而选择的功能用例，不是来自实地交通的随机统计样本。

本轮预测直接使用所构造的恒速运动，等价于完美当前位置和速度下的恒速外推。没有遮挡、观察范围限制、测量噪声或意图变化，不能把结果外推为复杂乡镇集市表现。

电动车条件为：正常25°C、低温−5°C、低温加较慢摩擦制动响应0.35 s三种。初始能量分数均为0.55。当前二维用例没有重新覆盖满电输入；此前纵向v2的SOC扫描保留，不能因此声称全部二维电池工况都已验证。

## 3 四种内部策略

| 策略 | 实现与用途 |
|---|---|
| nominal | 跟踪正常速度参考，不检查动态行人，用作检测碰撞的负对照 |
| slow_only | 全程跟踪较低速度参考，不依据横穿时机重新选择动作，用作低速并非总安全的负对照 |
| stop_wait | 先在横穿区之前停车，预测并检查后续起步方案；不合适则继续等待 |
| candidate | 使用同一名义执行模型比较直接、低速与停车等待的预测完成结果，选择预测无冲突且较早完成的候选 |

预测模型摩擦制动响应为0.18 s，实际执行可能为0.18 s或0.35 s。预测中还要求0.25 m附加行人间距，这是研究假设，不是法规或通用安全阈值。

candidate在入口选择一次方案，在停车等待时检查是否起步；行驶段内部尚不重新选择轨迹。它属于有限候选验证策略，不应称为完整在线MPC、连续重规划算法或已发表方法的复现。

当candidate的全部候选被拒绝时，返回no_plan，不执行未验证运动。它表示入口处拒绝进入，不能计为成功通行；初始状态本身若已接触，仍会记录该接触。no_plan分支不模拟后续长期等待。当前60组实际输入未出现该分支，其行为通过单独的拒绝候选测试检查。

## 4 实际结果

5种横穿时刻×3种车辆状态×4种策略，共60次确定性执行。每种策略15次。

| 策略 | 执行到达终点 | 无碰撞完成 | 出现行人碰撞 | 摊位碰撞或驶出道路 |
|---|---:|---:|---:|---:|
| nominal | 15 | 12 | 3 | 0 |
| slow_only | 15 | 12 | 3 | 0 |
| stop_wait | 15 | 15 | 0 | 0 |
| candidate | 15 | 15 | 0 | 0 |

nominal在中心经过时刻14 s的3种车辆条件下接触行人；slow_only在28 s的3种条件下接触。负对照说明“忽略动态对象”和“只降低速度”都可能失败，也说明当前检测链能捕获这些设定的接触。

碰撞后负对照仍继续执行，以便回放并检查几何；没有模拟碰撞力、车损或行人响应。因此它们“到达终点”不能解释为真实成功通行，不能把其终点时间用于安全策略的简单效率排名。

stop_wait无碰撞完成用例的平均模型完成时间约31.37 s，candidate约29.70 s。这只是当前内部候选选择的功能结果，不是相对已发表强方法的性能证明。

candidate的15次选择中，12次直接通过、3次停车等待，未选择全程低速候选。这说明低速候选在本轮没有成为最优选择，不能据此宣称已验证全部动作的优势。其实际采样最小行人间距约0.394 m。

当前各条件相互关联、数量很少，不能把计数转换为具有真实道路代表性的碰撞率或泛化结论。

## 5 车辆执行和几何验证

4项单元测试通过：前车身已接触但后轴参考点尚远离行人的情况；后部、侧面和角点间距；车体旋转后的接触与摊位检测；全部候选被拒绝时不执行运动。

2项回放检查通过：60条结果的分类一致性；保存的逐步车身碰撞、道路状态、转角及转角变化率与回放重新计算一致。位置更新还与保存的沿程位移一致，没有为避障而直接跳动车辆位置。

选择4个用例，将实际执行步长从0.02 s减小到0.01 s：两种负对照的碰撞标记保持一致；两个candidate用例仍无碰撞完成。停车再起步用例的最小间距变化约0.0405 m，完成时间变化约0.07 s，提示该模式对采样与重新起步检查时刻仍有敏感性。

以上检测仍是离散采样，不是连续时间碰撞保证。未来需要更严格的扫掠体检查或可证明的采样间隔条件，尤其在更快对象和更窄余量下。

## 6 文件与复跑

入口：crossing_2d.py；单元测试：test_crossing_2d.py；结果核查：verify_crossing_2d.py；绘图与局部动画：plot_crossing_2d.py。

在bev目录执行：

```powershell
python -m unittest -v test_crossing_2d.py
python crossing_2d.py
python verify_crossing_2d.py
python plot_crossing_2d.py
```

所有输出在results_crossing_2d：

- episodes.json、episodes.csv：60次执行结果及决策事件。
- 每个用例的_trace.csv：车辆、行人、车体间距和执行输出。
- 每个用例的_decisions.json：入口选择及停车后的检查记录。
- config_summary.json、experiment_manifest.json：模型设置、实验网格、代码哈希及结果。
- verification.json：回放与步长复核。
- crossing_overview.png：轨迹、速度、车身间距。
- crossing_local_replay.gif：冲突区8–22 s的局部回放，帧来自保存的实际轨迹，播放速度不等于仿真实时速度。

原始STV-ED与bev/results、results_stopping_v2均未覆盖。

## 7 下一项研究工作

首先建立“观测/预测”和“实际世界”的独立接口，再加入横穿开始时刻、速度或执行响应误差，保留未完成与碰撞结果。随后让行驶中的车辆定期更新候选，而不是只在入口和停稳后选择。

在此基础上，再比较固定时间裕量与执行状态相关时间占用，并与同样利用执行误差的空间约束方法比较。只有出现等价条件下的新能力或计算改进，才能进一步确定方法创新。

当前尚缺少车型标定、感知误差、突然出现对象、紧急回退、轮胎滑移和更复杂人流；不以本轮零碰撞用例证明真实场景安全。
