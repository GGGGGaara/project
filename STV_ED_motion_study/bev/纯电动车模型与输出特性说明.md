# 纯电动车模型与输出特性说明

日期：2026年11月3日。本阶段按通用单电机纯电动乘用车（BEV）建模。新能源汽车也包括插混、燃料电池等类型，本模型不覆盖这些动力系统。原始STV-ED和上一轮通用车辆模型均保留，新代码独立放在bev目录。

## 1 已完成的工作

已将“期望加速度直接施加到车辆”的理想执行方式，扩展为电机转矩、固定速比传动、道路阻力与再生/摩擦制动共同产生纵向运动的模型。横向仍采用运动学自行车模型和纯追踪控制，记录完整矩形车体通过两个冲突带的时间。

已经运行5种低速走停工况、4项单元测试和两种工况的步长细化检查。当前结果用于验证动力与制动执行机制，没有实现环境驱动的在线路径速度联合选择，也没有开展动态行人碰撞试验。

## 2 输出特性的依据与适用范围

MathWorks的电机模型以转矩需求为输入，包含电机及驱动器响应时间常数，并允许使用最大转矩/功率或转矩—转速包络。[官方模型说明](https://www.mathworks.com/help/autoblks/ref/mappedmotor.html)

MathWorks的再生与摩擦制动示例根据制动需求、速度和SOC分配制动转矩，并包含低速再生约束。总制动力需求可以由两类制动共同承担，不能由回收能力直接推导总制动能力。[官方示例](https://www.mathworks.com/help/sdl/ug/regenerative-friction-braking-control.html)

Tesla的车主手册说明，电池低温或接近满电时再生制动可能受限。这只用于佐证机制存在，不用于提供本模型参数，也不能推导所有车型的阈值或补偿标定均相同。[厂商说明](https://www.tesla.com/ownersmanual/model3/en_ie/GUID-3DFFB071-C0F6-474D-8A45-17BE1A006365.html)

| 特性 | 当前建模方式 | 需要避免的误解 |
|---|---|---|
| 低转速大转矩 | 低速最大转矩平台，达到功率限制后随转速下降 | 不代表低速可以无限加速，仍受控制、功率与附着条件限制 |
| 电机响应 | 一阶响应与转矩变化率限制 | 响应快不等于瞬时响应，轮端加速度也不是理想输入 |
| 再生制动 | 负电机转矩，受速度及充电功率限制 | 负转矩、电池回收功率和轮端制动力单位不同 |
| 低速回收衰减 | 合成速度相关限幅函数 | 衰减区间是研究假设，不是所有电动车的通用定律 |
| SOC和电池温度 | 限制充/放电功率 | 低温或满电不等于整车无法制动 |
| 摩擦制动补偿 | 根据已输出的电机制动力补足总需求，包含独立响应时间 | 不能故意移除补偿后再把失效归因于电动车 |
| 低速停车 | 简化制动与零速保持 | 没有实现量产车单踏板、蠕行或完整坡道保持策略 |

集市车速主要在低速区，高转速恒功率区域通常不是主要限制；优先关注低速制动分配、起停执行响应与通过时间。代码另外输出完整假设电机包络，用于核查转矩和功率约束。

## 4 模型与制动分配

固定传动比按无损齿轮处理，电气损失用合成效率表示：

\[
\omega_m=\frac{i v}{r},\qquad F_m=\frac{i T_m}{r},\qquad
m_{eq}\dot v=F_m-F_b-F_{roll}-F_{air}.
\]

电机正转矩限制同时满足转矩、机械功率与电池放电功率条件；负转矩受电机能力、低速衰减和电池充电功率约束。一阶执行环节与转矩变化率限制随后作用到电机实际转矩。

上层速度反馈给出期望加速度a_req，转换为总轮端力请求：

\[
F_{req}=m_{eq}a_{req}+F_{roll}+F_{air}.
\]

摩擦制动请求由实际电机轮端力补差：

\[
F_{b,req}=\max(0,F_{m,actual}-F_{req}).
\]

因此再生受限时，摩擦制动仍会补足需求；响应期间可能存在误差，稳态总制动力不应无故减少。已用正常、满电和低温三种执行器台架条件检验同一个减速度请求能否被满足。

电机机械功率为T_m·ω_m。驱动电功率按机械功率除以效率计算，回收电功率按负机械功率乘效率计算，再计入辅助用电。零速负速度截断和保持被简化，不能用于评价真实停止瞬间的舒适性。

## 5 实际运行结果

所有方法使用相同上层速度与横向控制逻辑：向x=10 m目标位置减速，低速停止后保持2 s，再驶向x=40 m停车。横向参考是一条小幅平滑偏移路径。控制器未针对各BEV状态重新优化。

| 工况 | 初始SOC与电池温度 | 第二冲突区离开时刻 | 电机侧累计回收电能 |
|---|---|---:|---:|
| 理想加速度执行 | 不适用 | 16.78 s | 不计算 |
| 正常BEV | 0.55，25°C | 16.58 s | 2.812 Wh |
| 满电附近BEV | 初始1.00，25°C | 16.08 s | 0.103 Wh |
| 低温BEV | 0.55，−5°C | 16.08 s | 0 Wh |
| 低温＋较慢摩擦制动响应 | 0.55，−5°C，响应0.35 s | 16.00 s | 0 Wh |

这是特定控制器、状态切换阈值和假设参数下的结果，不是量产车性能比较。**回收受限没有导致任务无法完成，也不能根据时刻更早推断其性能更好。** 首次停车的位置偏差约0.34–0.43 m，尚未达到严格停车位置跟踪的验证要求；必须先改善/标定控制器，再研究精确通行窗口。

满电工况并非始终零回收：车辆运动和辅助用电使能量分数略微下降，模型允许出现少量回收。能耗列另区分电池正向支出、净用电、电机侧总回收和摩擦耗散，不能直接混用。

两种电池状态下的第二冲突区离开时刻出现约0.5 s差异，提示动力与制动执行状态可能影响时间占用。它尚未证明规划器需要利用这些状态，也未证明利用后能改善安全或效率。

### 停车瞬间加加速度的数值效应

原始最大加加速度在若干工况达到15–31 m/s³。检查峰值位置发现，它们出现在接近零速时，与速度非负截断有关，不能解释为真实车辆制动切换的冲击。

输出因此另含速度大于0.2 m/s期间的最大加加速度，但这也只是诊断口径，不是合格的舒适性标准。后续需建立更平滑的终端停车/保持模型并统一滤波与评价窗口。

## 6 验证情况

4项单元测试通过：转矩—功率包络、再生限制、摩擦补偿后的稳态减速度，以及机械/电气功率方向与损失关系。

5种工况检查了任务完成、占用时序、速度非负、转角与转矩限制、能量分数更新一致性。正常和低温工况的步长由0.02 s减至0.01 s，冲突时间端点最大变化分别为0.03 s和0.01 s，首次停车位置变化均小于0.002 m。

这些是模型与代码一致性检查，不是实车标定、连续碰撞安全证明或论文级性能评估。尚无车轮滑移、ABS、完整轮胎模型、实际BMS图谱、热模型、感知和动态行人。

## 7 与论文主线的连接

当前目标仍是车辆运动规划：在可通行窗口变化的狭窄道路中，利用可用驱动/制动输出形成可执行的路径和速度，而不是另起一个以回收效率为唯一目标的课题。

候选状态可包含z=(x,y,ψ,v,T_m,F_b,SOC,温度)。研究进入/通过方案时，应区分正在驱动、再生减速、摩擦制动接入、停车保持及重新起步；不能把它们全部用同一个加速度时间常数替代。

必要的对照应在**同一个BEV执行模型**上运行：不感知执行状态的规划器、使用全局保守界的规划器、使用状态相关误差包络的方法，以及拟议方法。不能将一个方法放在理想执行器、另一个放在BEV模型上直接比较优劣。

电动化与复合制动本身已经有大量研究。例如2023年的双层控制工作已联合处理纵向运动与电机/液压制动分配：[出版方原文](https://www.sciencedirect.com/science/article/pii/S2590198223001136)。本方向的创新仍须在狭窄时变空间的可执行运动条件、时间占用计算或求解效率上建立，不能仅凭“采用新能源汽车”成立。

## 8 文件与运行

代码：`bev_probe.py`；单元测试：`test_bev.py`；工况核查：`verify_cases.py`。在此目录执行：

```powershell
python -m unittest -v test_bev.py
python bev_probe.py
python verify_cases.py
```

除可选绘图需要Matplotlib外，模型与测试只使用Python标准库。参数、工况结果、全过程转矩/制动力/电功率/车辆轨迹，以及验证记录均保存在results目录。图像为 `results/bev_stop_go.png`。

下一阶段应首先改善停车跟踪与零速模型，标定或系统扫描电机/摩擦制动响应及回收限幅，再将这些执行状态接入路径速度候选选择。现阶段结果不用于宣称已实现新的安全规划方法。
